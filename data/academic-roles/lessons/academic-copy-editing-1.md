## Outcomes

Define the boundary of a copy edit; apply a short style sheet consistently; distinguish a safe correction from an author query.

## Explain and demonstrate

An academic copy editor improves consistency, clarity and correctness while preserving the author’s intended meaning. The role differs from developmental editing, which may restructure an argument, and from subject assessment, which decides whether a technical claim is sound. The same passage can require all three, but responsibility must be explicit. Changing a technical condition without consulting the author can turn a readable sentence into an incorrect instruction.

Start with an editorial brief: audience, document purpose, language convention, referencing style, permitted level of intervention, deadlines and escalation owner. A style sheet records decisions such as heading case, acronym expansion, spelling and number presentation. It is a decision log, not a replacement for a referencing manual. Record exceptions when a vendor product name or quoted title uses a different convention.

### Worked example: edit or query?

Original synthetic sentence: “The learners data are stored secure and all users can delete it after the exam.”

| Issue | Appropriate action | Reason |
|---|---|---|
| “learners data” | Ask whether one or multiple learners; apply possessive form | Number affects punctuation |
| “stored secure” | Change to “stored securely” | Grammar correction preserves meaning |
| “all users can delete” | Query the authorized roles | Security meaning cannot be inferred |
| “after the exam” | Query retention timing and authority | The editor must not invent a policy |

A revised working sentence might read: “Learners’ data are stored securely. [Author query: Which roles may delete the records, and under what approved retention rule?]” The unresolved query stays visible. Do not silently turn “all users” into “administrators” simply because that sounds safer.

## Lab — create an editorial audit trail

**Setup:** Download the synthetic source handout and workbook from the course overview. Use tracked changes or save original and edited plain-text copies for a diff. No client documents are required.

1. Define six style decisions: English variety, heading case, acronym treatment, number convention, figure labels and referencing approach.
2. Edit the first two paragraphs of the supplied handout. Separate mechanical corrections from changes requiring subject confirmation.
3. Create a query log with an ID, original wording, question, reason, owner and status.
4. Add a change that deliberately alters a pass threshold. Ask a peer, or conduct a delayed second review, to identify why this is not an ordinary copy edit.
5. Restore the threshold and mark it for author confirmation if the source itself is ambiguous.

**Expected observations:** The edited version is more consistent, but unresolved policy or technical statements remain queries. **Evidence:** Original, tracked version, clean working copy, style sheet and query log. **Cleanup:** Remove the deliberately altered threshold from the clean copy and retain a labelled training example separately.

## Common pitfalls and teaching decisions

“Standardization” does not mean forcing every discipline into the same technical vocabulary. A synonym can change meaning: “authentication” and “authorization” are not interchangeable. Avoid rewriting a learner’s cultural or linguistic expression unless the agreed editorial purpose requires it. Explain a change in terms of audience understanding and document rules.

## Retrieval and reflection

<details><summary>Can an editor resolve a vague security permission by choosing a plausible role?</summary>

No. Query the accountable author or subject expert. A polished but invented rule is a substantive defect.

</details>

<details><summary>Why retain both tracked and clean versions?</summary>

The clean copy supports reading; the tracked copy supports review and accountability. Preserve a clear version relationship so reviewers know what changed.

</details>
