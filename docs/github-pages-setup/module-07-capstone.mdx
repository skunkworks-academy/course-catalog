## Guided lesson

### Scenario

A business needs a Docusaurus-based brand-guidelines site deployed from GitHub, available at a custom subdomain, with a controlled release workflow and evidence that the site can be operated safely.

### Deliverables

1. Repository with branch protection recommendations.
2. Docusaurus configuration for the deployment URL.
3. Build-and-deploy GitHub Actions workflow.
4. Public landing page and at least three content routes.
5. Custom 404 or route-recovery method.
6. DNS and domain-verification change plan.
7. HTTPS validation record.
8. Deployment test script and results.
9. Root-cause analysis for one injected failure.
10. Operations runbook and rollback procedure.

### Assessment rubric

| Criterion | Weight | Competent evidence |
|---|---:|---|
| Repository and build design | 20% | Reproducible source, supported runtime and valid static build |
| Deployment automation | 20% | Least-privilege Actions workflow with clear artefact handling |
| Domain and HTTPS | 20% | Correct DNS, verified domain, HTTPS and takeover controls |
| Validation and troubleshooting | 20% | Positive tests plus structured root-cause analysis |
| Security and governance | 10% | No secrets, protected release path and retirement controls |
| Evidence quality | 10% | Traceable commits, screenshots, logs and signed checklist |

## Applied exercise and assessment evidence

**Task.** Build the capstone website with three content routes, a custom-domain plan, a reproducible workflow, a route/asset verification script and a structured root-cause report for one injected failure. Submit redacted screenshots, logs, deployment commit and runbook.

**What to submit.** An evidence pack containing the configuration or plan, a short annotated diagram, command or workflow outputs where applicable, sanitized screenshots or illustrative figures explicitly labeled as simulations, and a one-paragraph reflection on failures or operational risks.

**Acceptance criteria.** All deliverables are traceable; the assessor can verify the published route, independently run checks and score each of the six rubric criteria.

**Assessor checkpoints.** Confirm technical correctness; verify that screenshots and logs identify the environment and date; ensure commands are reproducible; and confirm no credentials, personal data, private courseware or customer secrets are included.

:::note Evidence and privacy
GitHub Pages hosts publicly downloadable build artifacts. This training interface can hide lessons behind a browser access check, but does not make embedded static lesson content private. Submit confidential work to an approved authenticated LMS or evidence repository, not to a public Pages artifact.
:::
