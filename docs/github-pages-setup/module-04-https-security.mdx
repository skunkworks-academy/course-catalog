By the end of this module, the learner should be able to:

- Validate HTTPS redirect and hostname coverage after certificate issuance.
- Identify dangling DNS records and unclaimed Pages domains as takeover risks.
- Demonstrate that secrets and private learner records do not belong in static build output.

## Guided lesson

### 4.1 HTTPS enforcement

After DNS is correct and the certificate has been issued, enable **Enforce HTTPS**. Validate:

- certificate hostname coverage;
- certificate chain and expiry;
- HTTP-to-HTTPS redirect;
- mixed-content warnings;
- secure loading of fonts, images, scripts and styles.

### 4.2 Avoid dangling DNS

A DNS record that points to a Pages hostname after the repository or custom-domain association is removed can create takeover risk. Include DNS cleanup in repository retirement and domain migration procedures.

### 4.3 Avoid wildcard records

Do not use a wildcard record as a shortcut for Pages subdomains. Create explicit records for approved sites and maintain an ownership register.

### 4.4 Protect the deployment path

- protect `main` with pull-request review;
- require successful status checks;
- limit who can change workflow files;
- review third-party Actions;
- use environment protection for production where supported;
- keep deployment tokens and secrets out of site source;
- monitor Pages deployments and domain changes.

## Applied exercise and assessment evidence

**Task.** Design a domain security review checklist for your simulated deployment. Record certificate status, mixed-content checks, external script approvals, publishing permissions and what happens when the site is retired.

**What to submit.** An evidence pack containing the configuration or plan, a short annotated diagram, command or workflow outputs where applicable, sanitized screenshots or illustrative figures explicitly labeled as simulations, and a one-paragraph reflection on failures or operational risks.

**Acceptance criteria.** The security review clearly separates required controls, evidence gathered, risks outstanding and the named owner for follow-up.

**Assessor checkpoints.** Confirm technical correctness; verify that screenshots and logs identify the environment and date; ensure commands are reproducible; and confirm no credentials, personal data, private courseware or customer secrets are included.

Submit confidential work to an approved authenticated LMS or evidence repository, not to a public Pages artifact.
